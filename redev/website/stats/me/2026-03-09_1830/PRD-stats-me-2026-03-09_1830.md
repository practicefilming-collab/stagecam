# PRD: /stats/me Page Redesign

**Author**: redev session 2026-03-09
**Snapshot**: `03-09-2026-18-30.jpeg`
**Status**: Draft

---

## 1. Background

The `/stats/me` page is the authenticated user's personal stats dashboard. It answers "what have I recorded?" Currently it has five elements stacked vertically:

1. Header bar (app-wide)
2. Page title — "Your Role Call"
3. Summary stat cards (4-card grid)
4. Character role cards (per-character progress)
5. Recent recordings list (last 20 flat rows)

A critical review identified issues ranging from minor (title clarity) to severe (recordings list is unusable at scale). This PRD specifies the redesigned version of each element, ordered from least to most change required.

## 3. Element Redesigns

### 3.1 Header Bar — No Changes

The header bar is app-wide, clean, and functions correctly. Out of scope.

---

### 3.2 Page Title

**Problem**: "Your Role Call" is a clever pun but doesn't communicate the page's purpose to a new user. Someone arriving here for the first time has to scroll to understand what they're looking at.

**Requirement**: Add a subtitle that explains the page.

**Spec**:
- Keep "Your Role Call" as `h1` (gold, bold, 2xl)
- Add a one-line subtitle directly below: `text-sm text-muted`
- Subtitle text: "Your characters, progress, and recording history."

**Implementation**: Edit `page.tsx` only — add a `<p>` below the `<h1>`.

---

### 3.3 Character Role Cards

**Problems identified**:
1. Per-act progress bars are 1.5px tall (`h-1.5`). At low percentages the gold fill is invisible — the bars are decorative while the `x/y` numbers do the real work.
2. No role-size context: Andy (42 chunks) and Woody (274 chunks) look identical. A user seeing "WOODY 0%" doesn't know this is the lead role and 0% is expected.
3. `completionPct` uses `Math.round`, so 1/274 = 0.36% rounds to 0%. The user has done work but sees "0%" — feels like a lie.
4. "Toy Story (1995)" is repeated on every card. When the user has one script, this is noise.
5. No call to action — "I'm 17% on Andy, now what?"
6. Card ordering (by `totalRecorded` descending) is not labeled or explained.

**Requirements**:

#### 3.3.1 Thicker per-act bars
- Change per-act bar height from `h-1.5` to `h-2.5`.
- This matches the overall progress bar's `h-2` and makes low-percentage fills visible.
- **File**: `role-call.tsx` line 70 — change `h-1.5` to `h-2.5`.

#### 3.3.2 Role size indicator
- Below the script title line, add a muted label showing role weight: e.g., "42 lines" or "274 lines".
- Use `totalChunks` from the API response.
- Format: `<p className="text-xs text-muted/60">{totalChunks} line{totalChunks !== 1 ? 's' : ''}</p>`
- This lets users understand that Woody at 0% with 274 lines is a fundamentally different situation than Andy at 17% with 42 lines.
- **File**: `role-call.tsx` — add after the script title `<p>` on line 47.

#### 3.3.3 Fix 0% rounding
- When `completionPct` would round to 0 but `totalRecorded > 0`, display "< 1%" instead.
- **API change** (`route.ts` line 166): No change needed — keep returning the number.
- **Frontend change** (`role-call.tsx` line 51): Display logic:
  ```tsx
  {char.completionPct === 0 && char.totalRecorded > 0 ? '< 1%' : `${char.completionPct}%`}
  ```

#### 3.3.4 Group cards by script
- When the user has roles across multiple scripts, group cards under script headers.
- When the user has only one script, show a single script header above all cards instead of repeating the script name on each card.
- Script header format: `<h2 className="text-sm font-medium text-muted mb-2">{scriptTitle} ({scriptYear})</h2>`
- Remove the per-card script title line when grouped.
- **API change**: Add a `scriptId` field to each character entry (it's available in the map but not returned).
- **Frontend change**: `page.tsx` groups characters by `scriptId` before passing to `RoleCall`. `RoleCall` receives a new prop shape or the page handles grouping and renders section headers itself.

#### 3.3.5 "Continue" link on each card
- Add a tappable link at the bottom of each card: "Continue recording →"
- Links to the script's lobby/join page: `/scripts/{scriptSlug}` (or whatever the entry point is for joining a room for that script).
- Style: `text-xs text-gold/70 hover:text-gold mt-3 inline-block`
- This transforms the dashboard from informational to actionable.
- **Requires**: Confirming the correct link target for "go record more of this character." If no direct deep-link exists, link to the script's detail page.

#### 3.3.6 Explicit sort label
- Add a small label above the cards section: "Sorted by most recorded"
- Style: `text-xs text-muted/50 mb-2`
- Alternative: allow toggling sort (by % completion, by total size, alphabetical). Defer toggle to a future iteration — just label the current sort for now.

### 3.4 Summary Stat Cards

**Problems identified**:
1. "Recordings" vs "Unique Chunks" — when identical (34/34), why show both? When different, the distinction is unexplained.
2. "Unique Chunks" is developer jargon. Users don't know what a chunk is.
3. "1 Scripts" — grammar error (should be "1 Script"). With one script, the card is low-value.
4. "By Type" card: "13 dlg 20 act 1 hdr" — cryptic abbreviations, breaks the visual pattern of the other cards (no big number), cramped layout.
5. The four cards don't tell a story or motivate.

**Requirements**:

#### 3.4.1 Replace four cards with three meaningful ones

Remove the current 4-card layout. Replace with 3 cards:

| Card | Big Number | Label | Source |
|------|-----------|-------|--------|
| 1 | `{totalRecordings}` | "Takes Recorded" | `summary.totalRecordings` |
| 2 | `{characters.length}` | "Role{s} Played" | `characters` array length |
| 3 | `{overallCompletionPct}%` | "Overall Progress" | Computed: sum of all `totalRecorded` / sum of all `totalChunks` across characters |

**Rationale**:
- "Takes Recorded" uses film/theatre language instead of developer language. A "take" is universally understood.
- "Roles Played" is immediately meaningful and replaces the redundant scripts/unique-chunks cards.
- "Overall Progress" gives the user one number to track over time — the one thing they most want to know.

#### 3.4.2 Move type breakdown into a tooltip or expandable row

The dialogue/action/heading breakdown is useful for power users but not worth a top-level card.

- Add a collapsible row below the 3 cards: "View breakdown by type ▾"
- When expanded, show a horizontal stacked bar with labeled segments:
  - Dialogue (gold): `{n} dialogue`
  - Action (amber-700): `{n} action`
  - Scene heading (purple-400): `{n} scene heading`
  - Transition (cyan-400): `{n} transition`
- Use full words, not abbreviations.
- Collapsed by default. State does not persist across page loads.

#### 3.4.3 Pluralization
- All labels must handle singular/plural: "1 Role Played" vs "3 Roles Played", "1 Take Recorded" vs "34 Takes Recorded".

#### 3.4.4 Grid layout
- 3 cards in a single row on all screen sizes: `grid grid-cols-3 gap-3`.
- Each card: `bg-surface border border-gold/20 rounded-xl p-4 text-center`.
- Big number: `text-2xl font-bold text-gold`.
- Label: `text-xs text-muted mt-1`.

### 3.5 Recent Recordings List — Full Redesign

**Problems identified** (severity: severe):
1. 7 identical "ANDY INT. DOWNSTAIRS LIVING ROOM" rows — no user benefits from this repetition.
2. No grouping or collapsing mechanism.
3. Rows without a character name are unexplained (system chunks? action lines?).
4. No playback or tap affordance — rows look inert.
5. No pagination — renders all 20 at once, will get worse at scale.
6. Dominates ~60% of visible page with the lowest information density.

**Requirements**:

#### 3.5.1 Group by scene

Replace the flat list with recordings grouped by scene. Each group shows:

```
┌─────────────────────────────────────────────────────────┐
│  INT. DOWNSTAIRS LIVING ROOM                            │
│  Toy Story · Mar 8                                      │
│                                                         │
│  ANDY ×7        [▶]                                     │
│  (no role) ×2   [▶]                                     │
└─────────────────────────────────────────────────────────┘
```

**Group structure**:
- **Header**: Scene heading (white, sm, medium weight). Script title + relative date below (muted, xs).
- **Rows within group**: One row per unique character (or "Narrator" for null-character rows). Show count of recordings as "×N". Each row has a play button affordance on the right if/when playback is implemented.
- **"Narrator" label**: Rows where `character` is null should display "Narrator" in muted text instead of leaving a blank gap. These are action/scene-heading/transition chunks the user recorded without a character role.

**API change** (`route.ts`):
- Replace the flat `recentSessions` array with a grouped structure:

```ts
recentSessions: {
  sceneHeading: string | null;
  scriptTitle: string;
  date: string;  // ISO date (day only, not datetime)
  entries: {
    character: string | null;
    count: number;
    recordingIds: string[];
  }[];
}[];
```

- Group recordings by `(scene_id, date)`. Within each group, sub-group by character.
- Order groups by most recent first.
- Limit to 10 groups (not 20 flat rows). Each group may contain multiple recordings.

#### 3.5.2 Pagination

- Show the first 5 groups on initial load.
- "Show more" button at the bottom loads the next 5 (up to the 10 returned by API).
- If the user has more than 10 groups total, the API should support `?offset=N` for cursor-based pagination. Defer full pagination to a follow-up — for now, cap at 10 groups.

#### 3.5.3 Empty state

When the user has 0 recordings, the section should not render at all (current behavior is correct — the `recentSessions.length > 0` guard handles this).

#### 3.5.4 Tap target

- Each scene group card is tappable. On tap, navigate to the scene's panel page: `/panel/{sceneId}`.
- This requires the API to return `sceneId` in each group.
- Style: entire card is a `<Link>` with `hover:border-gold/40` transition.

#### 3.5.5 Section header rename

- Change "RECENT RECORDINGS" to "RECENT SCENES" — since we're now grouping by scene, the header should match.

## 7. Implementation Order

Ordered by dependency and risk:

| Phase | Scope | Files | Risk |
|-------|-------|-------|------|
| 1 | Subtitle, thicker bars, 0% fix, role size label | `page.tsx`, `role-call.tsx` | Low — purely additive frontend changes |
| 2 | Replace stat cards (3-card layout + collapsible breakdown) | `page.tsx` | Low — frontend only, no API change |
| 3 | Add `scriptId` to API, group cards by script, add sort label | `route.ts`, `page.tsx`, `role-call.tsx` | Medium — API additive change + frontend restructure |
| 4 | "Continue recording" links | `role-call.tsx` | Low — but requires confirming link target |
| 5 | Restructure `recentSessions` → `recentScenes` (API + frontend) | `route.ts`, `page.tsx` | High — breaking API change, must ship together |
| 6 | Pagination ("Show more") | `page.tsx` | Low — frontend state only (API already caps at 10) |

---

## 8. Out of Scope

- Header bar changes (app-wide, not page-specific)
- Playback from recording rows (future feature — tap targets are prepped but play functionality is not part of this PRD)
- Sort toggle on role cards (future — labeled sort is sufficient for now)
- Full cursor-based API pagination beyond 10 groups (defer until usage warrants it)
- Desktop/tablet layout optimizations (mobile-first per CLAUDE.md conventions)
